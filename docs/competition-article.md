# RAG校园助手：让校园信息"一问即得"

> 一个跑在 **COSMO Code** 平台上的校园智能问答应用——能听懂问题、会查资料、答得出就答、答不出就诚实说。

---

## 一、场景描述

### 📌 痛点是什么

**每年开学季，校园信息"太散了"。**

学校有 10+ 份官方文档（新生入学指南、教学与学习指南、生活与日常指南、奖助学金指南、收费标准……），但它们分散在不同文件里：

- 查"转专业需要什么条件" → 得知道去《教学与学习指南》找
- 查"食堂几点开门" → 得翻《生活与日常指南》
- 查"学费多少钱" → 又得去《收费标准与中外合作项目》

**一条简单信息，需要跨多份文档查找、人工拼凑。**

### 📌 影响多大

以我校每年约 **1.5 万名在校生**计，开学季的校园信息咨询是**高频刚需**：

- 学生平均查询一条信息要**翻 3-5 份文档、耗时 10 分钟以上**
- **新生尤其突出**——不知道该问谁、该去哪找，往往要反复询问学长学姐或辅导员
- 大量**重复性问题**（食堂时间、宿舍配置、转专业流程）消耗了学生和老师的精力

### 📌 现有方案的不足

| 方案 | 缺陷 |
|---|---|
| 通用大模型（ChatGPT / 千问 / 豆包） | 对校园专属信息**编造或答"不知道"**——非公开语料，模型没见过 |
| 传统关键词搜索 | 只返回零散片段，遇到**复合问题**（"食堂有几个？哪个离宿舍最近？"）束手无策 |
| 学校官网导航 | 要求用户**先知道去哪找**，门槛高，新生很难上手 |

**一句话：信息是有的，只是"找"太难。**

## 二、方案概述

**RAG校园助手**是一款面向在校学生的校园智能问答应用：学生用**自然语言或语音**提问，系统自动从 11 份校园官方文档中检索、重排并生成答案，**并标注来源**。

它基于 **RAG（检索增强生成）**技术构建，把"翻文档"变成"问一句"，让每个校园问题都能"**一句话问到答案**"。

---

## 三、如何体现"感知-推理-决策"

本应用不是"关键词匹配 + 拼接"的简单自动化，而是由大模型驱动的**理解—检索—推理—生成**闭环：

- **感知** —— 理解用户问题的意图，判断是单一问题还是复合问题，识别需要的信息类型
- **推理** —— 检索校园知识库 → 重排序筛选最相关片段 → 必要时**多步推理**（ReAct 循环：信息不足时自动改写查询、再次检索）
- **决策** —— 基于检索内容生成答案并**标注来源**；当知识库确实没有相关内容时，**如实说明"未找到"而非编造**

整条链路让系统"先想再查、边查边想"，最终给出**可追溯、可信赖**的答案。

---

## 四、核心亮点

**① 复合问题拆分**
通用大模型遇到「食堂有几个？哪个离宿舍最近？」只会答一个；本系统自动把问题拆成多个子问题，分别检索知识库后**分点作答**，每个点还各自标注来源。

**② 可溯源、不编造**
每条回答都标注引用的**来源文档**（如《生活与日常指南》）；知识库里没有的内容，系统**如实回答"未找到"**，绝不编造——答案可追查、可信赖。

**③ ReAct 多步推理**
不是"一问一答"就结束：当检索信息不足时，系统会**自动改写查询、进行多轮检索**，模拟人"边查边想"的过程，直到信息足够才给出答案。

**④ RAGAS 质量自评**
应用内置**自动化测评体系**（忠实度 / 相关性 / 正确性 / 检索精度 / 召回），不仅能问答，还能**给自己的答案打分**——问答质量用数据验证、可持续追踪。

## 五、使用方法

1. **进入应用** —— 打开地址即用，**无需注册登录**
2. **文字提问** —— 在输入框输入校园问题（如"转专业需要什么条件"），回车或点"发送"
3. **语音提问** —— 点输入框旁的**麦克风 🎤**，说话即可，系统实时把语音转成文字
4. **快捷提问** —— 点页面上方的**「高频问题」按钮**（食堂几点开门、奖学金怎么申请……），一键得到答案
5. **连续追问** —— 支持**多轮对话**，拿到答案后可继续追问（如"那具体流程呢？"）
6. **查看来源** —— 点答案下方的**「查看详细片段」**，核对引用的来源文档与原文

## 七、效果验证

**自动化测评（61 题 = 51 正常 + 10 超纲）**

| 维度 | 指标 | 得分 |
|---|---|---|
| 检索侧 | Context Precision（检索精度） | 0.500 |
| 检索侧 | Context Recall（检索召回） | 0.892 |
| 生成侧 | Faithfulness（忠实度） | 0.941 |
| 生成侧 | Answer Relevancy（相关性） | 0.941 |
| 生成侧 | Correctness（正确性） | 0.873 |
| 生成侧 | Overall（综合） | 0.918 |
| 防幻觉 | 正确拒答率（10 道超纲题） | 100% |

得分分布：**满分 40 / 部分 7 / 0 分 4**（技术故障 0）。

**与通用大模型对比**

| 维度 | 通用大模型 | RAG校园助手 |
|---|---|---|
| 校园专属信息 | 编造 / "不知道" | 基于官方文档、可溯源 |
| 复合问题 | 只答一个 | 拆分后分点作答 |
| 语音提问 | 不支持 | 支持 |
| 质量验证 | 无 | 内置自动化测评 |

**【诚实说明】** 测评中有 4 道题得 0 分、7 道部分得分，均为知识库未完全覆盖或信息不完整所致；而 10 道"超纲题"系统全部**正确拒答、零幻觉**——说明它**答不出时如实说明，绝不编造**。
